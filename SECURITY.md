# Политика безопасности

## Как сообщить об уязвимости

Не открывайте публичный issue с деталями уязвимости. Используйте приватный канал
GitHub: **Security → Report a vulnerability** (GitHub Security Advisories). Если
этот канал недоступен, откройте issue без технических подробностей и попросите
связаться для передачи деталей приватно.

В отчёте укажите: версию пакета, шаги воспроизведения, ожидаемое и фактическое
поведение, оценку влияния. Не прикладывайте реальные токены, персональные данные
и данные рабочего стенда — используйте синтетические примеры.

## Что считается уязвимостью

- Утечка `ELMA365_TOKEN` или других секретов за пределы процесса (в stdout, логи,
  сообщения об ошибках, артефакты сборки).
- Обход авторизации или выполнение запросов к ELMA365 с правами большими, чем
  задаёт токен.
- Инъекции в EQL/HTTP-запросы, позволяющие выйти за пределы предполагаемой
  выборки или приложения.
- Отказ в обслуживании (неограниченный рост памяти, неконтролируемые повторы).
- Уязвимости зависимостей, влияющие на обработку входных данных сервера.

## Что уязвимостью не считается

- Ограничения самого публичного API ELMA365 `/pub/v1` (например, отсутствие
  удаления/восстановления элементов) — это поведение платформы, а не дефект
  сервера.
- Доступ к данным, который разрешён правами приложенного токена: сервер не
  создаёт прав и не расширяет их.

## Что делает проект

- Токен читается только из окружения/`.env` и передаётся в заголовке
  `Authorization`; значения секретов не пишутся в stdout (он занят протоколом MCP)
  и не попадают в логи.
- В репозитории и CI выполняется автоматический поиск утечек (gitleaks) по всей
  истории.
- В примерах, документации и тестах используются только синтетические данные.

## Версии

Проект публикуется как `@chebser/elma365-mcp`. Исправления безопасности выходят
патч-версией; сведения — в [CHANGELOG.md](./CHANGELOG.md).
